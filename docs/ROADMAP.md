# 路线图

原则：每个里程碑都要**两版都能装进游戏跑**，不做"先写三个月再点亮"。
每个里程碑结束时更新 README 的功能表和兼容表。

### M0 待验证项（会影响后续设计，先做掉）

1. 解码 `Content.zip → Assets/Textures/Blocks.webp`，数清 256 格图集还剩多少空格
   → 决定联机版分级箱子的贴图方案。
2. 起一个自定义 `Block`（`static int Index = 700`）在**两版**里都能出现在创造栏、能放置、能挖掉。
3. 起一个自定义 `IPackage`（包号取未占用值），验证联机版客户端 → 服务端 → 回同步的闭环。
4. 验证 `.xdb` 新增 EntityTemplate + `SubsystemBlockEntities.CreateBlockEntity` 能创建自定义方块实体。
5. 验证 `OnWidgetConstruct` 能稳定拿到 `ChestWidget` 并往里塞按钮（两版）。

## M1 整理层（先做，最快见效，不需要新方块）

- 整理按钮注入所有库存界面；排序方式（类别/名称/索引/数量）
- 锁定槽位、记忆槽位
- 一键存入 / 一键取出（智能判据 + 全部存入）
- 撤销上一次整理
- 联机版：`StashOpPackage` + 服务端执行器 + 校验
- 单测：`StashSorter` 的合并/排序/锁定/差分最小化

## M2 分级箱子

- 6 档箱子方块 + 方块实体 + 可变行列 UI
- 升级件（原地升级、内容与命名保留、失败提示）
- 合成表（`.cr`）
- 联机版贴图方案落地（按 M0-1 的结论）

## M3 背包

- 三档背包物品 + 内容注册表（分配/写时复制/回收）
- 放地上变箱子、捡起来内容不丢
- 升级槽 + 第一批升级：拾取、磁铁、过滤、堆叠、自动存入、自动补货、垃圾
- 插件版：自定义衣物槽穿戴
- 单测：注册表生命周期、写时复制、世界身份校验

## M4 存储网络

- 枢纽（沿原版电线聚合容器）+ 增量刷新
- 终端 UI：搜索语法、排序、取放
- 合成终端（配方查询 + 自动抽料）
- 无线终端
- 性能基线：500 容器 / 8000 槽位下终端开启与刷新的帧时间预算

## M5 抽屉 + 绑定箱

- 1×1 / 2×2 抽屉，正面显示，容量/锁定/虚空升级
- 绑定箱（颜色配对，联机可按队伍隔离）
- 抽屉接入网络

## M6 打磨

- 触屏手势（拖过多格、双击补满）
- 容器命名 + 终端搜索联动
- 容器预览 HUD
- 死亡遗物箱（与 SCTM 死亡标记联动）
- 多语言（zh-CN / en-US 起步）

## v2 候选

- 按需自动合成（Refined Storage / AE2 思路）
- 背包外观与模型
- 第二批背包升级（压缩、熔炼、进食、工具替换、套娃）
