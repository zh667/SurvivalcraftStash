# 实机测试清单

这份清单只列**在 Linux 上验证不了、必须进游戏才能确认**的东西。
编译、单元测试、布局算术已经在开发机上过了，不重复。

所有诊断日志统一前缀 `[Stash诊断]`。出问题时先跑一遍：

```
grep "Stash诊断" Game.log
```

## 日志会不会被覆盖

**不会，是追加的。** 退出世界、退出游戏、重新进，之前的记录都还在，
所以「进创造测一轮 → 退出改成生存 → 再测一轮」这种来回切的测法是安全的，
一份 `Game.log` 里能装下整个过程。

两版的文件位置和滚动规则不一样（都是反编译源码确认的）：

| | 联机版 | 插件版 |
|---|---|---|
| 位置 | 游戏目录 `Bugs/Game.log` | `ModsManager.LogPath/Game.log` |
| 满了怎么办 | 超 **10 MB 直接清空**，无备份 | 超 **2 MB 改名备份**成 `Game <日期>.log` |

**联机版这条要留意**：超过 10 MB 是**整个清空**的，没有备份。
测一整天之前先看一眼文件大小，快到了就先备份一份出来。

联机版还有个开关：设置里 `LogMode = 1` 时改成按日期分文件（`Bugs/2026-08-13.log`），
跨天自动滚动。打算连着测好几天的话开这个更省心。

每行前面是 `HH:mm:ss.fff`，**只有时分秒没有日期**——
所以同一个文件里堆了多天的记录时，靠时间戳分不出是哪天，
按下面那条分隔线找当次的记录更快。

## 怎么定位「这一次进世界」的记录

每进一次世界（不是每次启动游戏）都会打一条分隔线，退出世界重进也会重新打：

```
[Stash诊断] ───── 第 3 次进入世界 ─────
[Stash诊断] 运行模式：权威端=True（…）
[Stash诊断] 方块索引：铜箱=693 铁箱=694 … 合成终端=708
```

所以换世界模式重测时，**只看最后一条分隔线之后的内容**就行。

`方块索引` 那行是给 A7 用的：两次进世界的这行摆一起对，
就知道索引有没有被重排、有没有被别的 mod 挤掉。
逐面贴图格号那种长输出只在**本次启动游戏的第一个世界**打一遍
（图集是进程级的，换世界不会变）。

   | A1 熔炉计时 | 创造即可 | 只要能拿到矿和煤 |
   | A6 浮层 UI | 创造即可 | 纯界面 |
   | A7 换世界 | 都行 | |

   **建议**：开一个生存世界当主力测试场，用作弊/创造只在需要快速拿材料时切一下再切回来。
3. 进世界后先确认这行在：

   ```
   [Stash诊断] 运行模式：权威端=True（…）
   ```

   单人世界 / 联机主机 = `True`，联机客户端 = `False`。
   **所有 `WorkType == Client` 的代码在单人世界一行都不会跑**，
   所以 A 组测完不等于联机没问题。

## A 组：单机（优先做完）

### A1. 分级熔炉的速度和燃料

创造模式，平地并排放：原版熔炉、铜熔炉、铁熔炉、钻石熔炉。
每个塞**等量**的煤和铁矿（比如各 8 个），同时点着。

不用掐表，日志会自己报：

```
[Stash诊断] 熔炉烧完一件：×4（×4）实测 1.7 秒 / 期望 1.7 秒，产物 铁锭×3，燃料剩 6
```

| 档位 | 倍率 | 每件期望耗时 |
|---|---|---|
| 原版 | — | 6.7 秒 |
| 铜 | ×2 | 3.3 秒 |
| 铁 | ×4 | 1.7 秒 |
| 钻石 | ×8 | 0.8 秒 |

- [ ] 实测和期望的差在 10% 以内
- [ ] **8 个矿烧完，四个炉子耗煤量一样**（高等级省煤 = 变相作弊，不能接受）
- [ ] 炉子不会自己烧起来（`FireDuration` 那个 bug 的回归检查）
- [ ] 炉子点着时没有火焰粒子 —— **这是已知的设计取舍**，不是 bug。
      联机版的火焰粒子认死了原版方块索引 65，我们不能把方块换成 65，
      否则整个炉子会被原版逻辑改回普通熔炉。插件版没这个问题。

### A2. 熔炉升级会不会吞东西

1. 放铜熔炉，**四类格子全塞满**：原料格铁矿、燃料格煤、产物格先攒几个铁锭、
   残留格弄点东西（烧含水的东西会出残留）。
2. **趁它正在烧**，手持铁升级件右键。

日志会打前后两行，直接对：

```
[Stash诊断] 熔炉升级：(12,64,30) 旧炉内容 0:铁矿×8, 2:煤×6, 3:铁锭×4（共 18 件）
[Stash诊断] 熔炉升级：(12,64,30) → StashFurnaceIron，新炉内容 0:铁矿×8, 2:煤×6, 3:铁锭×4（共 18 件）
```

- [ ] 前后两行的内容**完全一致**（数量一样，而且还在原来的格子里 —— 燃料不能跑到原料格）
- [ ] 提示语是「熔炉已升级」，不是「箱子已升级」
- [ ] 物品栏塞满时再升级一次，结果一样
- [ ] 拿**铜**升级件去点已经是铁的炉子 → 提示档位不对，炉子不变

出现下面这行说明兜底逻辑被触发了（东西掉地上了，能捡回来，但要报给我）：

```

```

### A3. 填材料（这次重写了核心路径，**优先测**，**必须生存模式**）

这块从"逐格搬运"改成了"先算完整计划再一次性落地"。单机也走新代码。

创造模式下按填材料只会提示「没有可取料的库存」，这是**故意的**，不是 bug——
理由见第 0 节那张表。

日志形如：

```
[Stash诊断] 填材料：目标 3×3（合成格，库存 ComponentCraftingTable），来源 2 块，权威端=True
[Stash诊断] 填材料：合成格现状 (空)
[Stash诊断] 填材料：计划 ComponentCraftingTable(id=7) 0←木板×1, 3←木板×1
[Stash诊断] 填材料：计划 ComponentInventory(id=2) 14←木板×62
```

**A3-1 基本功能**
- [ ] 工作台（3×3）：点配方 → 填材料 → 材料正确落到格子里，产物格出现结果
- [ ] 按 E 的 2×2：装得下的配方能填；装不下的提示「配方过大」
- [ ] 熔炉：点配方找「煤炭」（云杉木烧的），**「填材料」不能是灰的**，
      木头要进**原料格**，不能跑到燃料格

**A3-2 腾空逻辑（最容易吞东西的地方）**
- [ ] **物品栏塞满、一格空的都不留**，合成格里先手动放几个东西 → 填材料
      → 预期提示"退不回物品栏"，**且合成格里原来那几个东西一件不少地还在原位**
- [ ] 物品栏只留 1 格空，合成格放 3 种不同的东西 → 填材料 → 整个放弃，什么都没动
- [ ] 合成格里已经放着**正好是这个配方要用的**材料 → 填材料 → 应该能复用，不该报缺料
- [ ] **换配方时旧材料要回到"已经有这东西的地方"**：从终端取 4 个木板 → 换成熔炉配方
      → 木板要回到终端里那摞木板上，而不是塞进行囊的空格。
      日志里这行会说清楚去了哪：
      `填材料：腾空 木板×4 → ComponentStashChest 槽12×4（合并）`
- [ ] **通配配料不能吃染色件**：手上同时有原色木板和白色木板 → 合成工作台
      → 只能消耗原色的。日志里出现 `0←白色 木板×1` 就是回归了。

**A3-3 取料来源**
- [ ] 材料全在行囊里、物品栏一个都没有 → 能填
- [ ] 材料一半物品栏一半行囊 → 能填
- [ ] 材料不够 → 提示缺什么，**合成格保持不动**

任何一步之后，物品总数都不能变。日志里的"计划"几行加起来就是全部改动，
搬入和搬出必须对得上。

### A4. 无线合成终端的 3×3 格子

这块格子挂在**玩家身上、跟着存档走**，关界面不会自动清空。

- [ ] 打开终端 → 3×3 里放几个东西 → **不合成，直接 ESC** → 重开 → 东西还在原位
- [ ] **退出世界、关游戏、重进** → 东西还在
- [ ] 3×3 放好木板 → **只取走一半产物** → 关界面重开 → 剩下的材料数对得上
- [ ] 进世界时这行的槽位数必须对上：

- [ ] 产物名显示「无线合成终端（xxx）」，带着原来的绑定名

## B 组：联机（一个人也能做）

### 怎么一个人测两端

netmod 是直连式的：一边开服，另一边给 IP 就能进（有游客模式，不需要账号撮合）。

**推荐：手机 + 电脑。** 两边装同一份 mod，同一个 WiFi。
电脑开房当主机，手机连电脑的内网 IP。手机那台就是真正的客户端。

**备选：同一台电脑开两个实例。** 反编译源码里**没有单实例互斥锁**，
复制一份游戏目录、开两个进程可行，一个开服，另一个连 `127.0.0.1:端口`。
缺点是两个窗口抢焦点。

进去后先确认客机那台打的是 `权威端=False`，否则测的还是主机路径。

### B1. 填材料（本轮改动最大的地方）

上一版在这里有两个吞东西的 bug（原版 `AcquireItems` 在客户端直接返回 0
什么都不做，而返回值语义是"剩余数量"，看起来正好像"全收下了"）。
现在改成客户端把计划发给服务端、服务端校验守恒后落地。

在**客机**上：
- [ ] 合成格里先放几个东西 → 填材料 → 提示「已请求服务端填料…」，
      稍后格子被服务端刷新成正确内容
- [ ] **合成格里原来那些东西必须回到物品栏，不能消失**
- [ ] 主机那边看客机的物品总数，前后守恒
- [ ] 服务端日志里不该出现 `[Stash] 拒绝一次整理请求：物品不守恒`
